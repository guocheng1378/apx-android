## 〇、本次更新要点（三端「功能 ↔ 入口」覆盖审计后的修正）

审计结论：**不是每个功能都有入口** —— 存在若干"假入口"（点了没反应）与"缺入口"。本轮逐条修掉：

- **TV 端**：新增「开启 / 停止被控」（此前**只能开不能关**，服务和开机自启永久常开）；
  自检清单补齐**输入法 / 虚拟手柄 / 通知权限**三项；注入通道状态改为**轮询到就绪**
  （evdev / root / uinput 都是异步的，以前只刷 3 次会让状态行长期停在"未开启"）；
  手柄与电源动作**有了界面反馈**（以前按了完全看不见）；副屏页加**屏上返回按钮**；
  主界面 4 张演示卡片不再谎称"已打开：xxx"；手机侧发来的「开副屏」请求不再被丢弃。
- **手机端**：**全屏操控面加入口**（此前唯一入口是"被控通知"，而通知要先开被控 → 鸡生蛋）；
  设置页新增「被控状态与注入通道」自检与「运行日志」（`Log` 的 512 条环形缓冲此前没有消费者）；
  操控面的遥控键盘补齐**电源 / 关机 / 重启**（与主页横屏键盘一致）；
  遥控键说明更新为"**真方向键** vs 只移动光标"；布局套数文案统一为 8 套。
- **电脑端**：Web「连入 / 断开」不再假装可用（改为如实说明"连接在桌面面板"）；
  Web 副屏分辨率**参数对齐后真正生效**（此前发 `{w,h}` 而后端只认 `preset`，静默无效）；
  副屏开关 / 插入虚拟显示器 / 剪贴板 / 蓝牙**明确标注为"只切后端"或"当前不可用"**，不再静默成功；
  三个默认全局热键（副屏循环 / 音频路由 / 重新发现）从"未知动作"**补成真实行为**；
  PC 当被控时的**手柄从空实现改为键盘+鼠标降级**（按钮→键盘等价键、左摇杆→鼠标）。
- **如实标注**（做不了就不假装）：`clipboard.push/pull`、`bluetooth.pair` 返回明确"不可用"；
  Web 控制台不含无线连接；删除零引用的 `web/js/**`（12 个文件，实际服务的自包含 `index.html`）。
- **本轮仍未做 / 已知边界**：面板内"发送文件到手机"按钮 —— 发送逻辑在**托盘右键菜单**
  （已可用）。面板用的是自绘布局引擎，加按钮要改布局/绘制/命中/事件 5 处且无法在本环境做
  GUI 回归，故**只标注入口在托盘**，未加面板按钮；如需面板按钮可单独排。
- 另有两条构建侧说明：`APXPC_BUILD_UI=OFF` **并未真正守卫** `apxdesktop` 目标（传了也照样产出面板）；
  手机端 `ui/README.md` 里"GamepadController 只有 USB 出口"的旧描述已更正（现在还有网络帧出口）。

## 二、签名说明（重要）

- **Android APK**：使用工程内置自签 keystore（`apx-release.keystore`，alias `apx`，30 年证书）签名，可 `adb install` 直接安装、可侧载/内部分发。
  - ⚠️ 自签证书**不能上架 Google Play**（Play 要求 Play App Signing 上传密钥）。若要发布到商店，需替换上传密钥。
- **PC exe**：仅 Release 编译，**未做 Windows Authenticode 代码签名**（本机无 EV 代码签名证书）。
  - 本机/内网双击可运行；对外分发会被 SmartScreen 拦截，需你提供 `.pfx` 证书后由我们补一步 `signtool` 签名。

## 四、使用方法

### 场景 A：手机当 PC 的无线外设 / 遥控器
1. PC 运行 `apxhost.exe`（常驻）+ `apxdesktop.exe`（面板）。
2. 手机安装 `app-release.apk`，进入**触控板**页（竖屏默认）。
3. 点右上角「设备」chip → 选列表里**自动发现**的 PC（后面标 `(PC)`）；PC 会自动被发现，无需手填 IP。手填 IP（「手动输入 TV IP」）只用于 TV。
4. 连上后即可：触控板控鼠标、全键盘页打字、多媒体控制；蓝牙 HID / USB HID 外设模式按需求在设置开启。

### 场景 B：手机被 PC / 另一台手机控制
1. 手机进入**触控板**页 → 打开「**被控模式**」开关（`ControlledService` 启动 9511 服务端 + 广播信标）。
2. **必须开启系统「无障碍服务」**（否则只显示对方光标浮层、不真正注入；通知栏会提示“仅可视化”）。
3. 控制方（PC 或另一台手机）在设备 chip 里选中该手机 → 即可控。

### 场景 C：两台手机互控 + 互传文件（都只装 app）
1. 两台手机连**同一 Wi-Fi**。
2. 手机 B：触控板页开「被控模式」+ 开无障碍服务。
3. 手机 A：触控板页点设备 chip → 选 B（显示为 `APX1TV` 或 B 的 IP）→ A 直接控 B。
4. 传文件：A 在触控板页点「发送文件」按钮 → 选文件 → 发往 B 的 9512 端口；B 静默存到 `应用外部文件/APX/<文件名>`（无需存储权限）。
5. 反向同理：B 也开被控模式、A 也开被控模式，即可**双向实时互控、双向互传**。

### 场景 D：手机当 PC 扩展副屏
1. PC 运行 `apxdisp.exe`，手机在无线副屏页连 PC（走 9502 媒体通道）。
2. 副屏触摸按扩展屏区域归一化回传 PC。

### 场景 E：Android TV 被控
1. TV 安装 `tv-release.apk` 并运行，自动广播 `APX-TV` 信标、起 9511 服务端。
2. 手机/PC 在设备 chip 里选 TV 即可控。

### 场景 F：USB 有线控制（手机 ↔ PC）
- 已默认开启 `GadgetFeature.NCM`（本次修复）。插 USB 线后手机挂 USB 网卡，PC 经 `APX1TV` 信标发现并连 9511，走有线控制。
- USB 外设（HID 键鼠/声卡/COM 口）与 USB 副屏（FFS `apx` 端点）功能保持完好。

## 五、注意事项

1. **网络**：无线控/发现依赖**同一局域网**（信标是 LAN UDP 广播）；跨网段/公网不可用。USB 有线不受此限。
2. **无障碍权限**：被控方（手机/ TV）务必开启无障碍服务，否则仅可视化不注入。
3. **被控模式开关**：被控前必须手动开启「被控模式」并保持在后台（前台服务保活，通知栏常驻）。
4. **PC exe 未签名**：外发会被 SmartScreen 拦，仅建议本机/内网使用，或提供 pfx 后补签名。
5. **自签 APK 不上 Play**：商店发布需更换 Play 上传密钥。
6. **设备名辨识**：被控手机广播名是字面量 `APX1TV`，在设备列表里不如真实机名直观；发现异常时可手填对方 IP（「输入 TV IP」）。
7. **副屏握手未真机联调**：`apxdisp↔9502` 仅代码层（空令牌一致）确认，建议首次使用真机验证一次。
