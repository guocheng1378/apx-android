# 全能外设 更新日志

> 详细用法见 [`docs/使用说明.md`](./使用说明.md)；发版流程见 [`docs/RELEASE.md`](./RELEASE.md)。
> **版本线**：v0.4.0 起变更明细随 **GitHub Releases** 随 tag 自动发布（tag 为真源）；

## Unreleased

**横滑切分组滑杆冲突修复（成宇 2026-11-10「鼠标调节高度，键盘高度，这两个和滑动切分组冲突，界面调节调节时界面会跑」）**：

- 根因：横滑判定挂在父级先看的事件通道上，子控件（滑杆）对拖动的消费**永远不可见**——每个新事件都是干净的未消费实例，56dp 阈值一到就翻组并吃掉剩余序列，滑杆拖一半页面跑了。
- 修法：判定改挂子级先行的通道——滑杆、滚动列表先处理事件，同一事件里它们的认领当场可见，手势立刻让路；空白处的横滑没人认领，照常翻组。

**界面缩放跟手修复（成宇 2026-11-10「界面缩放不丝滑」）**：

- 去掉主壳缩放上的 150ms 缓动：那是档位跳变时代（离散档一步一跳）加的平滑；滑条改连续后它每次拖动都重启 tween，界面永远落后拇指一小截地「追」、松手后还多渲染一段尾巴。缩放值只有滑条一个写入方且步进极小，直接读即是逐帧实况预览，天然平滑。

**横屏四指切页修复（成宇 2026-11-10「横屏的四指切页好像不能用」）**：

- 根因：四指滑在 `dispatchTouchEvent` 里只改 `pageState`（普通字段），指望 `LaunchedEffect(pageState)` 双向同步 —— 但改普通字段不触发重组，同步 effect 不再执行，界面纹丝不动（其余切页入口都是同时写 `page` 与 `pageState` 两份，唯独四指这条路踩空）。
- 修法：`pageState` 改为快照状态（`mutableStateOf`），任何一处写它都让读它的组合失效，四指切页即时生效；顺带让四指切到触屏/键盘页时低栏自动收起等联动一并跟上。

**设置页一指横滑切分组（成宇 2026-11-10「设置页的分组切换不方便」+「就按这套做」）**：

- 设置页整页支持一指横滑切分组：向左滑下一组、向右滑上一组（与横屏四指切页同方向），页签保留不动；切换后回到组顶、翻组给一下触感。
- 冲突仲裁靠事件归属：滑杆 / 滚动列表一认领拖动手势即退出（在滑杆上怎么拖都不会翻组）；横向 > 2×纵向且超 56dp、单指才触发，与竖滑收低栏方向正交；一滑只翻一组，双指落下即放弃。

**低栏切页自动收起（成宇 2026-11-10「悬浮低栏进入触屏页或键盘页要自动隐藏」）**：

- 进入触屏页 / 键盘页时悬浮低栏自动收成球，回到状态页 / 设置页自动展开 —— 全屏操控面不再被胶囊压住操作区；手动上滑收起、点球展开照常可用（手动展开后不会被切页逻辑立刻按回去）。

**横屏真键盘找回（成宇 2026-11-10「横屏我设计的键盘布局怎么没有了」）**：

- 根因：b17 方案 C 的横屏 FULL 真键盘在「建面板那一刻」就定型 —— 本壳 Activity 声明
  `configChanges`（旋转不重建）后，两处横屏判定都跟不上旋转：
  ① 操控面键盘页（`TouchpadActivity`）的面板在 `onCreate` 一次成型，旋转后从不重建，
  横屏分支永远不再进入；② Compose 键盘页 `QuickLayout` 读 `LocalConfiguration.orientation`，
  正是 v223.29.8 记录过的「回写滞后一拍」老坑（修了低栏、漏了键盘）。
- 修法：操控面 `onConfigurationChanged` 就地重建键盘页（`modBtns` 随旧面板作废统一重登记，
  保持当前页签，重建后补同步 sticky 高亮）；Compose `QuickLayout` 改读
  `rememberApAdaptiveLayout().landscape`（窗口实测，与布局测量同源，永不滞后）。

**HIG 落地批次二（画面页失败就地重试）**：

- 触控板/TV 连接（`TouchpadActivity` 画面页动线）失败时，不再只有转瞬即逝的 toast：改为就地弹窗给出失败原因与「重试」按钮，一次点击按原地址原类型重连；文案与批次一设备选择器同一口径（HIG Agency：失败给可操作的出路）。
- 概览页经评估不再新增：Android 状态页已合并「状态概览 + 三通道开关 + 连接信息 + 模块状态」，与 PC 面板 Overview 对应，另立一页只会重复。

**HIG 落地批次一（连接失败可重试）**：

- 设备选择器连接失败不再只有一句转瞬即逝的提示：选择器内联显示失败原因（确认电脑端已打开全能外设、同一网络），并附「重试 · 设备名」按钮就地重连 —— 最近连接与扫描列表两条动线都覆盖（HIG Agency：让用户从错误中恢复，不锁死在流程里）。

**投屏到电脑**（手机屏幕 → PC 实时画面）：

- 手机端新增 `screenmirror` 包：`ScreenMirrorActivity`（MediaProjection 授权，成功后拉起前台采集服务）+ `ScreenMirrorService`（mediaProjection 类型前台服务：VirtualDisplay + ImageReader RGBA → 等比缩放至宽 720 → JPEG q65 → ≈10fps 节流 → `MediaOut.camera` 复用 streamId=6 上行）。
- Manifest 声明 `FOREGROUND_SERVICE_MEDIA_PROJECTION` 权限并注册新组件（Android 14+ 要求 mediaProjection 前台服务先于 getMediaProjection）。
- PC 端与桌面壳新增 `screenmirror.toggle` action（与 camera.toggle 同口径：下发失败如实报错、不改开关态）；开投屏同步打开预览窗。
- 网页面板画面页新增「投屏到电脑」卡片与开关；docs/PROTOCOL.md 注明屏幕采集复用 stream 6。

## v223.29.33（2026-11-08）

互传（LocalSend）发现链路修复（触发线：手机端互传开关开着，电脑端「附近设备」永远是空的）。

### 现场取证（真机 + 真进程，先证伪再改）

- PC 端 `apxdesktop` 53317 在听、防火墙规则 `AllPeriph apxdesktop ctrl v2` 放行、多播组 224.0.0.167 已加入、双向 HTTP（`/api/localsend/v2/info`）全部正常。
- 但 PC 日志里 40 分钟**零条**来自手机的 announce（历史 11 条全是本机回环 / 排查探针）。
- 反过来用 `adb shell nc -u 224.0.0.167 53317` 在同机手发一条同样的 announce，PC 立刻打印「发现设备（192.168.2.182）」 —— 网络多播与 PC 接收都没问题，是 App 自己没发。
- App 的发现 socket（`[::]:53317`）能收包（灌包测试 drops 涨到 7 万），但应用层毫无反应；整个模块零日志、异常全被空 `catch` 吞掉，出问题时现场什么都不留。

### 手机端（`LocalSendService`）

- 发现 socket 改成**显式 IPv4**：`MulticastSocket(null)` + `bind(0.0.0.0:53317)` + 指定 Wi-Fi 网卡 + `TTL=1` + `SO_BROADCAST`。旧写法按平台默认地址族绑到 `[::]`、`joinGroup(..., null)` 让内核自己挑网卡，多网络（Wi-Fi + 蜂窝）下「入组网卡」与「出口网卡」不一致时 announce 就发不出去。
- 发现主循环改**自愈**：任何异常都记日志（tag `ApxLocalSend`）、关旧 socket、指数退避后重建并重新入组；单条报文解析失败不再带走整条通道（旧实现 `receive()` 抛一次即永久退出）。
- announce 同时发**多播组 + 受限广播 + 网段广播**：家用 AP 对 224.0.0.167 做 IGMP snooping 丢包时靠广播兜底。
- `register` 请求体补 `port` / `protocol`（官方 `RegisterDto` 字段）：缺这两个字段对端记不进设备表，多播被挡时唯一的兜底通路等于不存在。
- 设置页新增「发现通道未就绪」提示：服务在跑但发现线程没起来时不再假装正常（新增 `LocalSendService.discoveryUp` / `httpPort`）。

### PC 端

- `POST /register` 缺 `port` 不再静默丢弃：回落到默认 53317 并入表，入表日志标注「body 无 port，按默认端口」。
- 面板启动日志占位符 `%u` / `%s` 改成 `{}`（此前日志里一直原样打印「互传接收端已启动：端口 %u」，最该看的端口号看不到）。

## v223.29.23（2026-11-07）

对着 issue#166（成宇「安卓端布局/弹窗/交互」反馈 + 评论「过长内容要换行或滚动、同类控件文字要对齐」）做的一批收口。

### 弹窗

- `DialogCard` 的限高从 `fillMaxHeight(0.62)` 改成 `heightIn(max = 屏高×0.62)`：
  此前**每条弹窗都被撑成大半屏**，两行字 + 一个按钮的确认框也占 62% 屏高，
  按钮离正文老远，观感就是「弹窗又大又空」。现在内容短就贴内容收，长了才顶到上限并滚动。
- 弹窗宽度加 `widthIn(max = 560.dp)`：横屏/平板上 `0.94 × 屏宽` 会变成 800dp 级的巨卡
  （真机横屏实测：一列开关被拉成相隔 700dp 的两道边）。
- 弹窗补入场动效（0.94→1 缩放 + 淡入，走 `ApMotion` 弹簧）：此前是「啪」地出现；
  设置页「动效」关掉时退化为 0ms，直接落终态。

### 编辑页横向溢出（issue#166 第 1 条的真身）

- 新增 `ui/kit/FlowRow`：框架自带没有「排满就换行」的 ViewGroup（Flexbox/ConstraintLayout
  的 Flow 都要额外依赖，本模块只有 Compose + Miuix），这里手写一个最小实现。
- 自定义键盘编辑页：12 颗键此前全塞在一条 `LinearLayout(HORIZONTAL)` 里，
  每颗 28dp 内边距加文字，在弹窗宽度里**必然溢出 —— 右侧几颗画到屏外、点不到**。
  现在「行操作 + 加键」单独一行，键位走 `FlowRow` 自动换行，并回显「N 颗」。
- 快捷键编辑弹窗的修饰键（Ctrl/Alt/Shift/Win…）同样改成 `FlowRow`：
  窄屏 + 大字号时最后一项会被挤出屏幕右边。

### 交互与动效

- 四页切换补 190ms 上浮 + 淡入（此前 `when(page)` 硬切，像换了个应用）；
  只有新页参与动画，不同时挂两页（避免触控板/键盘页的手势订阅短暂翻倍）。

### 震动全丢（成宇 2026-11-03：「震动也没有，还有其他震动也没了」）

**这不是「位置放错」，是振动被系统整条丢掉了。** 真机取证（2509FPN0BC / HyperOS 4）：

- `settings get system haptic_feedback_enabled` = **0**，由此 `dumpsys vibrator_manager`

`USAGE_TOUCH`），而这两档恰好被系统开关判成 OFF → 静默丢弃。**仓库里没有任何代码写过
这个系统开关**（全仓 `rg` 为空），所以不是本版改坏的；它是历史行为，只是这轮把
「设置页里选了『强』照样不震」暴露出来了。

修法（两处，收口到 `Feedback.haptic`）：

- `Feedback.haptic`：`createOneShot` 与 `createWaveform` 都显式带

  `computeSdk` 35 可直接调）。语义就是「硬件/按键反馈」，比 UNKNOWN 准确，也不再依赖
  ROM 怎么推导；该档在本机是 MEDIUM。
- `ScreenActivity.buzz`（副屏遥控页点按）：仓库里**第二处**自己拿 `Vibrator` 的地方
  （`Feedback` 的 KDoc 写「全项目只有这一处」，此处是漏网之鱼），既不带属性、又绕开
  设置页档位（选「关」照样震）。已改为直接调 `Feedback.haptic`，全项目 Vibrator

## v223.20.1（2026-11-01）

热修 v223.20 的**首启闪退**：装上点开就黑屏退出，进不了界面。

### 根因

`ApShellActivity.onCreate` 在 `setContent {}` **之前**调 `applyImmersive()`，里面读
`window.insetsController`。Android 15/16 的 `PhoneWindow.getInsetsController()` 直接读
尚未赋值的 `mDecor` 字段 —— DecorView 还没安装时它**抛 NPE，而不是返回 null**，
所以 `?: return` 这种写法挡不住。v223.20 恰好把 LAUNCHER 从旧主界面切到
`ApShellActivity`，潜伏的这行就成了「一开就崩」。

### 修法

改成 `window.decorView.post { ... }`：DecorView attach 到 Window 之后再取 controller，
未 attach 时先排队 —— 不漏执行，也不会再抛。其余 Activity 的同类调用都在
`setContentView()` 之后，本来就没有这个窗口期。

### 影响面

只动 Android 手机端的 `ApShellActivity`（主入口）。逻辑层、PC 端、电视端无改动。

## v223.18（2026-11-01）

本版接 issue #52 的**第 13 条**（遥控器页）与**第 5 条**（蓝牙不成 HID 键鼠），两条都有源码级根因。

### 修了什么

- **遥控器页的虚拟触摸板在 USB / 蓝牙模式下等于废掉**（第 13 条后半）。
  `RemoteActivity` 的触摸条**直接**读 `ControlTarget.controlClient?.mouse(...)`，只覆盖
  「无线 9511」一条链路；而**同一页**的方向键 / 确认 / 返回走的是 `HidKeys` → `Uplink.resolve`，
  USB 与蓝牙都通。于是插线用遥控器时——按键有反应、光标一动不动，只能得出「触摸板坏了」。
  现在新增 `hid/HidMouse.kt`，把鼠标与多媒体键的三条真实出口收拢成一处（判据仍是
  `Uplink.resolve`）：无线 9511 → `TvControllerClient.mouse`；USB → rid 0x02
  `[rid, buttons, dx, dy, wheel, pan]`；蓝牙 → `BtHidDevice.reportMouse`；三条都没有 →
  记 `Uplink.NONE` 并**返回 false**，界面按失败处理，不再静默丢帧。
  `RemoteActivity` 的移动 / 单击 / 按下提示与目标行文案全部改走它。
- **光标浮层开关（0x32）在非无线出口下不再静默无反应**：浮层是**被控端**画的，USB / 蓝牙
  没有这个能力，过去点了毫无反馈。现在切到被控端能力之外会提示「连上受控设备后才出现，
  开关已记住」，偏好照旧持久化。
- **蓝牙 HID 的两处硬缺口**（第 5 条「配对之后系统还是识别为 pad / 手机」）：
  1. **`BtHidDevice.connect(host)` 全仓没有任何调用点** —— Android 只把 HID SDP 注册上去，
     HID profile 的连接必须有一端主动 connect，而两端当时都没人做。现在注册成功后
     向**已配对的电脑 / 电视**（majorDeviceClass = COMPUTER / AUDIO_VIDEO）主动补一次连接；
     不往耳机 / 车机 / 另一部手机上乱连。
  2. **没有蓝牙开关监听**：Android 在蓝牙关闭时会拆掉 profile proxy，注册随之失效，
     而旧实现从不重注册 —— 用户「为了配对去关一次蓝牙再开」之后就一直显示成手机，
     只有重启模块才恢复。现在挂 `ACTION_STATE_CHANGED`（API 33+ 用 `RECEIVER_NOT_EXPORTED`），
     关闭时如实降级、开启时自动重注册；`start()` 先看开关，蓝牙没开就 DEGRADED 并说明，
     不再永远停在 STARTING。
  - 注册时把 SDP 子类与描述符长度落日志，便于定位主机为什么这么认。

### 实现方式

- `RemoteActivity` 的触摸条不再自己择路；出口判据只有 `Uplink.resolve` 一处。
  鼠标帧格式复用既有约定：USB 侧 rid 0x02、蓝牙侧 rid 0x01（`sendReport` 负责 Report ID，
  载荷不含 ID 字节），与触控板模块完全同源。
- `HidMouse` 只服务「低频、单发」场景，**不复制**触控板模块的 USB 背压状态机
  （失败帧合并、16ms 补发）：两处各养一份积压状态会互相打架。
- 蓝牙重注册走幂等的 `openProxy()`，已拿到 proxy 就只补注册，避免代理泄漏。

### 需要真机确认

1. **遥控器页**：USB 有线接电脑、蓝牙连电脑两种情况下，触摸条滑动能否移动光标、单点能否点击。
2. **蓝牙 HID**：先在**主机端删掉本机旧的配对记录**再重新配对（旧的缓存有设备类型，
   App 侧改不了），然后看电脑是否认成键鼠。若仍显示成手机，请把
   `蓝牙 HID 注册状态=…` / `注册 HID：subclass=…` 那几行日志发上来。
3. 蓝牙自动连不上时，界面会怎样提示（目前只有「自动连已配对的电脑 / 电视」这条路径，
   **还没有**「手动选择主机」的入口 —— 如果自动连不成功，这条需要补 UI，请反馈）。

## v223.17（2026-11-01）

本版修的是 issue #52 里**两轮都没定位**的那条：实体键盘转发（第 6 条「退后台收不到按键」
与第 11 条「打快了概率性触发系统功能键」）。根因有真机日志实证，不是推测。

### 修了什么

- **窗口转发桥在主用例里根本没挂上**。转发桥靠包装 `Window.Callback` 拦按键，而它原先
  **只**在 `TouchpadFragment.ensureViews()` 里挂一次 —— 那是幂等的一次性守卫，首次调用
  若拿不到 Activity，此后所有调用都被挡回，桥就**永远**挂不上。
  真机日志（pad，v223.15）里：`MIUIInput` 记录 **2477 条按键全部到达**
  `MainActivity` 的 ViewRootImpl，而**同一时段本进程除它之外一条日志都没有** ——
  桥在链上的话，那 2477 次 `dispatchKeyEvent` 必然各留一行 `ApxBridge KEY`。
  一条都没有 = 桥没挂。
- **无障碍那条路的长按语义和窗口那条路分叉了**。v223.14 修「长按只出 2 个字符」时
  只改了 `PhysKeyBridge`；声称「逐条对齐」的 `GlobalKeyForwarder`（无障碍 `onKeyEvent`）
  仍是 `HidKeys.combo`（60ms 自动释放）—— 释放窗口被系统自动重复事件反复续期，
  只发一次「按下」、**又始终不发「抬起」**，而 Windows / macOS 对**注入**按键不做自动
  重复，于是无线模式下长按恒只出一个字符。
- **抬起丢失没有自愈**（第 11 条的真机制）。转发是有状态链路：按下才发、抬起才放，
  而 `ACTION_UP` 并不保证送达（退后台、切应用、系统丢帧都会丢）。丢了以后电脑侧会一直
  按着那个 Ctrl / Shift，此后敲的**每个**字母都带修饰发出 —— 表现正是「输入过快时
  触发系统快捷键 / 输入错乱」。

### 实现方式

- `PhysKeyBridge` 新增 `ensureAttached(window)`：幂等（重）挂载，已在链上返回 false、
  不在就重新包装；窗口回调被别人换掉时**不还原**（硬塞回原回调会踩掉别人的包装），
  只重新包一层并打一条日志，便于下次日志直接看出自愈发生过。
- 宿主 `MainActivity` 自己持有桥并在**每次 `onResume` 复核**；全屏操控面的
  `TouchpadActivity` 同样复核；`TouchpadFragment` 不再挂第二份（两处各挂一份会互相拆包装）。
- `GlobalKeyForwarder` 按 `PhysKeyBridge` ⑤ 逐条对齐：首次按下 `hold()` 按住不放；
  无线 9511 下每次系统自动重复补一对「释放 → 按下」造出真实边沿；USB / 蓝牙 HID 下
  对端是真键盘设备、重复由对端负责，本机忽略；抬起 `releaseHold()`。
- 新增 `PhysKeyBridge.releaseStuckKeys()` 与 `GlobalKeyForwarder.resetKeys()`，
  在 `onPause` 与转发开关关闭时放掉残留按键，把状态拉回零点。

### 顺带核对掉的一条旧账

- v223.15 的 `accessibility_service_config.xml` **没有** `canRequestFilterKeyEvents`
  （v223.16 才补上），所以当时「退后台收不到按键」是**两个缺口叠在一起**：窗口那条路
  没挂桥、无障碍那条路拿不到按键路由。两者本版都已闭环。

### 需要复测

1. 开「物理键盘全局转发」+ 系统无障碍后，把 app 退后台，实体键盘敲字能否到电脑。
   若仍不行，请导出日志 —— 现在能一眼区分断在「桥没挂」「无障碍没收到」「开关没开」。
2. 无线模式长按字母 / 退格是否连续出字符（原先只出 1 个）。
3. 快速连打后是否还会概率性触发系统快捷键。
4. 回归：主页触控板页与全屏操控面里实体键盘是否都可用。

### 本版未做（等你确认后动）

### 建议 6 · 不把 app 挂前台也能用键鼠

该能力在 Android 上分两条腿，各自独立开关、独立门槛：

- **键盘腿（无需 root，默认关）**——PR #54 已合入

- **触控板腿（需 root，默认关）**——PR #56 合入，#57 修正
  - 触控板位移没有对应的无障碍事件：外接指针的原始位移被系统当**光标**消费，

    `open` 该字符设备），只解析 `EV_REL`（X/Y/WHEEL/HWHEEL）与
    `BTN_LEFT/RIGHT/MIDDLE`，在 `EV_SYN` 处成帧。
  - `RootPointerBridge` 把位移喂 `TouchpadModule.feedPointer`，与屏上触摸、
    窗口 hover **同一出口**；按钮位图持久保留（否则「按住拖动」会在第二帧断）；
    接管时令窗口 hover 通路让位，避免位移双计。
  - 拿不到 root 或没接指针设备时**如实提示**，仍走原窗口通路，不显示假的「已开启」。

### 修正（PR #57）· 真机内核无 mousedev 时指针设备发现必空

真机复验（小米 15 / Android 15）发现 #56 的设备发现逻辑在该内核上**静默失效**：

- `cat /proc/bus/input/handlers` 只注册了 `leds / evdev / input-boost / xiaomi-fp /
  xiaomi-touch / kgsl` —— **没有 mousedev**；`/dev/input/` 下只有 `eventN`、
  没有 `mouseN` 节点，全机设备 `mouseN` 出现 **0 次**。
- 原实现只认 Handlers 里的 `mouseN`，于是恒返回空、开关开了也不接管
  （与问题 5「状态显示与实际不符」同类）。

修法：判据改为「`mouseN` **或** 能力位图（`EV` 含 `EV_REL` 且 `KEY` 含 `BTN_LEFT`）」
取或，并改用 `eventN` 定位节点。触摸屏是 `EV_ABS`、键盘无 `EV_REL`、手柄无 `REL`，
据此都不入选；自家虚拟设备按名字继续排除以防自激。

## v223.3（2026-10-27）

### 修复（macOS 触控板完全没反应）
- **相对位移在 macOS 上是空操作，光标纹丝不动**。#47 第 6 条反馈
  「无线模式下实体键盘触摸板、app 内虚拟触控板都不可用，但键盘输入可用」——
  键盘走 `CGEventCreateKeyboardEvent`，触控板走 `injectMouse`，差别就在后者：
  旧实现把增量写进 `kCGMouseEventDeltaX/Y`，**落点却仍传当前坐标**

  增量字段只是事件自带的信息、不驱动光标 —— 于是每一帧都等价于「把光标移到它现在
  所在的位置」，看起来就是触控板完全没反应。

- 同一处顺带修掉四件事：
  - 每次移动都漏一个 `CGEventCreate(nullptr)` 造出的事件对象（连续滑动时是无上限泄漏）；
  - 按住键时的移动原来投递 `kCGEventMouseMoved`，改为 `kCGEvent(Left|Right|Other)MouseDragged`
    —— 否则部分应用收不到拖拽（选区、拖文件、拖窗口）；
  - 右键 / 中键一律传 `kCGMouseButtonLeft`，改为各自的 `CGMouseButton`；
  - 顺序改为「先结算按键状态、再移动、最后滚轮」：反过来的话「按下 + 同帧位移」
    会在键还没按下时先发拖动，「抬起 + 同帧位移」会把拖拽尾巴判成普通移动。
- 落点夹取到**全部活动显示器的并集**（副屏在主屏左侧时 origin 为负，不能只夹主屏）；
  取不到显示器列表时不夹，避免把光标吸到 (0, 0)。
