## 〇·零、v198：三端交互逻辑排雷

### 一、远程输入：补齐另一半，并修掉「取消等于白点」

- **PC 作被控端时远程输入全部落空**：`Ctrl9511Server` 的 `onRequestInput` / `onRemoteInputText` /
  `onRemoteInputDone` 三个回调在 `desktop_main.cpp` 里**从未注册** —— 手机上敲的字经 `0x26` 发到
  PC，PC 既没注入也没日志（上一版只修了 PC 作**控制端**那一个方向）。
- **退格发不出去**：`sendInputText()` 开头 `if (text.empty()) return false` 把空文本一律拒掉，
  而「退格帧」的语义恰恰是**文本为空 + flags 0x02**。PC 上每按一次退格都返回失败并弹"没发出去"，
  对端一个字也删不掉。
- **点「取消」不撤销**：`INPUT_FLAG_CANCEL(0x08)` 三端接收侧全是空实现（`-> Unit`），TV / 手机上
  点了取消，对端已上屏的字一字不少地留在那儿。现在与 PC 同口径：按剩余字数逐个发 `0x02` 退格
 （`0x08` 仍照发，语义保留给将来三端实现「整段撤销」）。
- **协议方向注释写反**：头文件把 `0x25` / `0x26` 记成单向「控制端 → 受控端」，实际是
  **谁有输入框谁发**。方向记反，正是 `0x26` 在受控端被当成"不可能收到的帧"、从而没注册回调的原因。

### 二、TV 端：两个回调没接上、一个端口永不重试

- **`0x10` 模块开关空转**：TV 端从未注册 `onModuleToggle`，PC 面板拨「无线」开关时 TV 只打一行日志
  —— `suspendAccept()` / `resumeAccept()` 永不调用，PC 关掉无线后 TV 仍在接受并注入输入。
- **9502 媒体口一失败就永不重试**：`ensureMedia()` 在 `start()` 失败时仍把实例赋给 `media`，之后
  每次调用都在第一行 `return`。开机自启时 Wi-Fi 尚未就绪 → 副屏永久黑屏、电脑声音永久不出，
  只能重启进程。现在失败不落实例，下次调用自然重试。

### 三、PC 端：三处会真出事的

- **断链后 socket 被关两次**：reader 线程退出时无锁 `closeSock` 且**不置** `kBadSock`，上层判定链路
  失效后立刻重连 —— Windows 的 SOCKET 值已被新连接复用，于是"刚连上就被旧线程关掉"，表现为
  反复重连 / 刚连即断。现在两处收尾统一在锁内关闭并置空。
- **栈越界 1 字节**：`sendRequestInput` 的 `uint8_t b[1+255]` 在 hint 满 255 字节时被
  `memcpy(b+2, …, 255)` 写穿（还附带一个无效的 `b[0]=0x25`）。
- **剪贴板回环**：文本注入走「写剪贴板 → Ctrl+V → 还原」，这一段**没进抑制窗口**，watcher 把中间态
  经 `0x21` 回传给对端，对端剪贴板被刷乱（`setSystemClipboard` 早有这层保护，这条路径漏了）。
- **新会话不清发送队列**：没有对端时剪贴板每变一次就入队一帧，手机一连上就被灌一串历史旧内容。
- **退出时并发 join**：`stop()` 先 join beacon，而 worker 内部也在 join / 重建它 —— 对同一个
  `std::thread` 并发 join 会 `terminate`。改为只 join worker，beacon 由它收（并留兜底）。
- **面板在断线宽限期内停止刷新**：宽限分支直接 `return`，把整个 tick 掐断，控制面抖动的那 3 秒
  里面板完全不刷新、设备下拉也不更新，抖得频繁时看着像"假死"。

### 四、多媒体键被注入两次

`0x02` 多媒体位图在 `ControlServer.onConsumer` 里先调 `endpoint.consumer(bitmap)`（已完整处理
bit0~bit6），紧接着又按 `CONSUMER_MAP` 逐位补一次按键 —— 点一次「播放/暂停」来回切两次、看起来
毫无反应；按「电源」连发两次；有 root 时音量一次跳两档。已删掉重复的那圈。
（手机端 `TvControlServer` 的第二圈是**界面反馈** `TvInputDispatcher`、不是注入，故保留。）

### 五、本版产物

- `AllPeriph-v198-app-release.apk` —— 手机端
- `AllPeriph-v198-tv-release.apk` —— Android TV 被控端
- `AllPeriph-v198-apxhost.exe` / `-apxdesktop.exe` / `-apxsetup.exe` —— PC 端

验证：三端均构建通过；手机端装机零崩溃；协议一致性校验 48 项通过、1 项已知警告（`0x05`）。

### 六、已知遗留（本版未修，需单独设计）

- **TV 在后台时收不到「请你输入」**：`0x25` 目前靠 `MainActivity` 的动态广播接收，主界面没打开或
  已被回收就静默丢弃。常驻需要在 Service 侧接收，而 Android 10+ 对后台启动 Activity 有限制，
  需走「通知 + 点击」方案。
- **`0x28` 特殊键 / 组合键**：只有 PC 控制端实现了接收，手机控 TV / 手机控手机时被控端无分支、
  静默丢弃（当前 `TvControllerClient.sendSpecialKey` 无调用点，暂不影响使用）。
- **`0x06` 请求关键帧**：只有发送方、三端零接收，切回副屏只能等周期 IDR（断连后会黑屏数秒）。
- **握手没有版本协商**：新旧版本互通时新帧被静默丢弃，也无法提示"请升级"。

## 〇·一、v197：触控板交互反馈 + 远程输入三端打通

### 一、触控板：手势反馈补齐，顺带修掉两个"完全没生效"的功能

反馈的根子问题不是"没做"，而是**做了但那条路是坏的**：

- **长按震动失效**：`TouchpadModule.armDrag()` 用 `VibrationEffect.createPredefined(EFFECT_CLICK)`，
  各 ROM 对预置效果的支持不一，不少机型直接没反应；而且它**绕过了设置页的震动档位** ——
  用户在设置里选了"关"，长按照样震。现在全项目只有 `Feedback.haptic()` 一处真正调 Vibrator：
  振幅与时长自己给（不受 ROM 效果表影响），并且尊重档位设置。
- **新增反馈**（此前完全没有）：双指滑动**进入**滚动、双指捏合缩放、双指点按（右键）、
  三指按下（中键）、双指长按（右键拖拽）。只在**状态切换点**震一下 —— 滑动过程中逐帧震
  会变成持续嗡嗡声，也很费电；抬起再落下算新的一轮。
- **修：双指捏合缩放完全失效** —— `twoFingerBaseDist` 声明之后**从来没有赋过值**，恒为 0，
  于是 `if (twoFingerBaseDist > 0f)` 永远进不去，用户怎么捏都没反应（Consumer Report 缩放位
  一帧都没发出去）。现在第二指落下时量基线，新一轮触摸重新量。
- **修：右键拖拽是死功能** —— `armRightDrag()` 全仓库**零调用点**，等于没有这个能力。
  现在双指落下 550ms 触发，与左键长按对称。
- **界面补一行字**：长按锁定后手指还压在屏幕上、液态光标被手挡住，光靠震动无从判断
  （况且震动档位是可以关掉的）→ 显示「已锁定拖拽 —— 移动手指即可拖动」，1.6 秒后自行收起。

### 二、远程输入：三端对等

- **发起端接上了**：手机 / TV 的输入框获焦 → 自动请对端弹输入法（帧 `0x25`）。
  此前 `ApxAccessibilityService.onFocusDetected` **全仓库零注册点**，无障碍服务检测到的焦点
  事件被丢掉 —— 这就是「调用手机输入法的功能没有了」的根因。
- **电脑端补上反向**：`Ctrl9511Client.onRequestInput` 从未被注册，手机 / TV 反过来请电脑打字时
  电脑毫无反应（此前只有托盘「让手机帮我输入…」一个方向）。新增「对端请你输入」窗口
  （`pc/host/src/ui/remote_input_win32.cpp` + 会话层 `sendInputText` / `sendInputDone`）。
- **回传的字以前根本没落地**：TV 端收到 `0x26` 只打一行日志、手机端干脆是空实现 ——
  对端弹了输入法、用户也打了字，字却哪都没去。现在按 `INPUT_FLAG_*` 注入到本机当前聚焦的
  输入框（`typeText`，被 ROM 拒绝时退 `paste` 兜底）。
- **只发增量，不再补整段**：PC 端按**宽字符**算公共前缀做 diff（按字节会把一个汉字拆成
  3 次退格，对端会多删两个字）；发送按钮不再补发 COMMIT(`0x04`) —— 增量 + 整段重粘
  正是 `340856f` 修的那个「发送后文字重复两次」。取消也不发 `0x08`（三端都没有处理方），
  改成逐字退格把已上屏的字撤掉。
- **防回环**：发出 `0x25` 到收到回传期间不再发新的，否则
  「注入文本 → 输入框再获焦 → 又发一次请求」会让对端输入面板无限弹。

> 已知边界：电脑端**自动**请对端输入（Windows 上检测输入框获焦）未做 —— 需要 UI Automation，
> 侵入与权限成本都不小；目前电脑 → 手机 / TV 仍走托盘右键「让手机帮我输入…」。
> 手机作为**控制端**请求 TV / PC 输入（`TvControllerClient.requestInput`）也仍是零调用，
> 缺一个 UI 入口。

## 〇·零·一、v186：手机端文案全部进资源

上一版把词汇表与色板钉死之后，这一版把**手机端的用户可见文案整体搬进 `strings.xml`** ——
此前 1100+ 处中文字面量散在 Kotlin 与布局 XML 里，改一处措辞要翻上百个文件，
"被控 / 受控 / 对端"三套说法就是这么长出来的。

- **新增两个搬运工具**（默认预览、`--apply` 才落盘，`scripts/` 下）：
  - `kotlin_i18n.py`：只认"确定是 UI 文案"的调用形态（Toast / 对话框 / `text=` /
    本项目辅助函数 / if-else 三元等）；`$x` 与 `${表达式}` 插值转位置参数；跨行拼接合并；
    多行调用向上认领开括号；**Activity/Fragment 之外的文件整份跳过**（`getString` 需要
    显式 Context，要迁得先改函数签名）；`val/var` 属性初始化一律不迁（同样没有 Context）。
  - `xml_i18n.py`：布局的 `android:text / hint / contentDescription` → `@string/`。
- **迁入规模**：Kotlin 侧 235 处（主页 / 操控面 / 遥控 / 文件面板 / 副屏五个界面文件）
  ＋ 布局 68 处 → 约 245 条资源，全部语义命名；相同文案只留一条
  （"取消"全局一条，"无线 / 蓝牙 / USB"跨页共用 `lay_transport_*`）。
- **同步修掉的术语违规**（逐条过词汇表）：注入通道 → 权限；受控 / 对端 → 被控设备 / 手机；
  9512 / 9502 端口号 → 人话；HID 键码 / 多媒体位图 → 效果描述；`HID 未就绪` → 键盘还没就绪；
  `电池未加白` → 省电白名单；`0 帧` → 还没收到画面；`minLevel` / `延迟预算` → 日志级别 / 连接状态；
  关机确认框补上谓语（"关机 被控设备？" → "要对那台设备执行「关机」吗？"）。
- **页面元数据改为资源 ID**：`PAGE_TITLES / PAGE_SUBS` 存 `intArrayOf(R.string...)`，
  取字符串移到有 Context 的 `showPage()` —— companion object 里没有 Context，这里翻过一次车。
- **仍未迁（下一批）**：object / 辅助类里的文案（HotkeyBoard / KeyboardPanels / HotkeyTemplates /
  HidKeys / GadgetManager / AgentController / 两个 TvInjector / TvControlServer 等，约 300 处）
  —— 需要先给函数签名加 Context 参数；以及两个界面文件里剩的 ~27 行嵌套模板
  （`${if (...) "a" else "b"}` 形态，机械转换会出错）。

## 〇·一、v185：三端「文案 + 视觉语言」统一

出发点是三条用户视角的问题：**同一个东西在三处有三种叫法、把研发进度与工程指标摆给用户看、
把内部实现词（端口号 / UDC / Gadget / evdev）当界面文案**。本轮按「三端一套词汇表 + 一套色板」收拢。

### 词汇表（写死在 `android/app/src/main/res/values/strings.xml` 头部 —— 改文案前先读它）

- 控制端 =「手机 / 电脑」；被控端 =「本机」；被控制的那台 =「被控设备」；动作 =「接受控制」
- 动作词收敛：开关用「打开」、服务用「启动 / 停止」、应用用「退出」、连接用「断开」
- 功能名收敛：触控板（不写「触摸板」）、副屏（不对用户写「镜像 / 投屏 / 推流」）
- **禁止出现在用户文案里**：端口号、UDC、Gadget、ConfigFS、UAC2、HID、evdev、minLevel、内核路径、adb / logcat

### 手机端

- **状态页重做**：删掉「已实现 / 尚未接通（计划中）」两张清单（等于把路线图当说明书给用户看），改为
  「打开开关后，手机就变成电脑的外设」+ 8 条收益导向说明；`UAC2 音频`、`蓝牙 HID`、`IMU / NMEA / CDC ACM`
  等实现词全部换成"能得到什么"。
- **工程指标下架**：「延迟预算 · 触控上行 ≤2ms」→「跟手程度 + 不跟手怎么办」；
  「启用模块 N 个」（内部模块位图计数）从状态摘要里删除。
- **状态行去术语**：「UDC / Gadget」→「USB 外设状态」；`SuperSpeed / 480Mbps` →「USB 3.0 高速 / USB 2.0 慢档」；
  root 说明去掉 `/sys/kernel/config/usb_gadget` 路径，但保留"为什么必须 root"的完整解释。
- **失败文案**：连不上 / 发文件失败 / 主题导出失败一律补成「现象 + 原因 + 下一步」；
  「这不是主题文件」→「这个文件不是主题文件 —— 选之前「导出」生成的那个」。
- **无障碍**：无线 / 蓝牙 / USB / 快捷键自动排序四个 Switch 与每个模块行开关补 `contentDescription`
  （此前读屏只会念"开关"）。

## 〇、本次更新要点（三端「功能 ↔ 入口」覆盖审计后的修正）

审计结论：**不是每个功能都有入口** —— 存在若干"假入口"（点了没反应）与"缺入口"。本轮逐条修掉：

- **TV 端**：新增「开启 / 停止被控」（此前**只能开不能关**，服务和开机自启永久常开）；
  自检清单补齐**输入法 / 虚拟手柄 / 通知权限**三项；注入通道状态改为**轮询到就绪**

  手柄与电源动作**有了界面反馈**（以前按了完全看不见）；副屏页加**屏上返回按钮**；

  操控面的遥控键盘补齐**电源 / 关机 / 重启**（与主页横屏键盘一致）；
  遥控键说明更新为"**真方向键** vs 只移动光标"；布局套数文案统一为 8 套。
- **电脑端**：Web「连入 / 断开」不再假装可用（改为如实说明"连接在桌面面板"）；

  副屏开关 / 插入虚拟显示器 / 剪贴板 / 蓝牙**明确标注为"只切后端"或"当前不可用"**，不再静默成功；

## 四、使用方法

### 场景 A：手机当 PC 的无线外设 / 遥控器
1. PC 运行 `apxhost.exe`（常驻）+ `apxdesktop.exe`（面板）。
2. 手机安装 `app-release.apk`，进入**触控板**页（竖屏默认）。
3. 点右上角「设备」chip → 选列表里**自动发现**的 PC（后面标 `(PC)`）；PC 会自动被发现，无需手填 IP。手填 IP（「手动输入 TV IP」）只用于 TV。
4. 连上后即可：触控板控鼠标、全键盘页打字、多媒体控制；蓝牙 HID / USB HID 外设模式按需求在设置开启。

### 场景 B：手机被 PC / 另一台手机控制
1. 手机进入**触控板**页 → 打开「**被控模式**」开关（`ControlledService` 启动 9511 服务端 + 广播信标）。
2. **必须开启系统「无障碍服务」**（否则只显示对方光标浮层、不真正注入；通知栏会提示“仅可视化”）。
3. 控制方（PC 或另一台手机）在设备 chip 里选中该手机 → 即可控。

### 场景 C：两台手机互控 + 互传文件（都只装 app）
1. 两台手机连**同一 Wi-Fi**。
2. 手机 B：触控板页开「被控模式」+ 开无障碍服务。
3. 手机 A：触控板页点设备 chip → 选 B（显示为 `APX1TV` 或 B 的 IP）→ A 直接控 B。
4. 传文件：A 在触控板页点「发送文件」按钮 → 选文件 → 发往 B 的 9512 端口；B 静默存到 `应用外部文件/APX/<文件名>`（无需存储权限）。
5. 反向同理：B 也开被控模式、A 也开被控模式，即可**双向实时互控、双向互传**。

### 场景 D：手机当 PC 扩展副屏
1. PC 运行 `apxdisp.exe`，手机在无线副屏页连 PC（走 9502 媒体通道）。
2. 副屏触摸按扩展屏区域归一化回传 PC。

### 场景 E：Android TV 被控
1. TV 安装 `tv-release.apk` 并运行，自动广播 `APX-TV` 信标、起 9511 服务端。
2. 手机/PC 在设备 chip 里选 TV 即可控。

### 场景 F：USB 有线控制（手机 ↔ PC）
- 已默认开启 `GadgetFeature.NCM`（本次修复）。插 USB 线后手机挂 USB 网卡，PC 经 `APX1TV` 信标发现并连 9511，走有线控制。
- USB 外设（HID 键鼠/声卡/COM 口）与 USB 副屏（FFS `apx` 端点）功能保持完好。

## 五、注意事项

1. **网络**：无线控/发现依赖**同一局域网**（信标是 LAN UDP 广播）；跨网段/公网不可用。USB 有线不受此限。
2. **无障碍权限**：被控方（手机/ TV）务必开启无障碍服务，否则仅可视化不注入。
3. **被控模式开关**：被控前必须手动开启「被控模式」并保持在后台（前台服务保活，通知栏常驻）。
4. **PC exe 未签名**：外发会被 SmartScreen 拦，仅建议本机/内网使用，或提供 pfx 后补签名。
5. **自签 APK 不上 Play**：商店发布需更换 Play 上传密钥。
6. **设备名辨识**：被控手机广播名是字面量 `APX1TV`，在设备列表里不如真实机名直观；发现异常时可手填对方 IP（「输入 TV IP」）。
7. **副屏握手未真机联调**：`apxdisp↔9502` 仅代码层（空令牌一致）确认，建议首次使用真机验证一次。
