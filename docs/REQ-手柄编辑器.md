# REQ：手柄编辑器改版方案

- 状态：方案评审中（2026-11-13，成宇）。用户原话：「手柄模式在手机界面有问题，编辑逻辑是否有问题，看看开源项目怎么做的，还有改键方式」；本批只出方案不动代码，经确认后按分期实施。
- 关联：issue#169 第 18/19/20/21 条（编辑体系既有实现）；`docs/REF-PROJECTS.md` > 手柄编辑器范式（2026-11-13 调研，许可已核）。
- 涉及文件：`android/app/src/main/java/com/allperiph/ui/GamepadActivity.kt`（1019 行）、`GamepadPadConfig.kt`（132 行）、`res/values/strings.xml`。

## 一、现状梳理

编辑体系（issue#169 第 18–21 条落地后的形态）：

- **两态模式**（Moonlight 式取两态）：普通态 = 纯游戏输入，长按多久键就按多久；编辑态 = 不发 HID，✎ 进 / ✓ 出（`padEditing`）。
- **手势分区**（`Pad` 组件，GamepadActivity.kt 921–1009）：编辑态按住拖动 = 移位（松手 `setOffset` 落盘）、按下点落在外圈 12dp 边缘环 = 捏边无级缩放（`PAD_RESIZE_MIN_DP=36` / `MAX=120`，每帧 `setSize` 落盘）、tap（未过 slop）= 弹配置卡。
- **对齐吸附**（第 19 条，175–180、325–366）：拖动中与其它槽位中心差 ≤ 7dp 吸上并画轴线；基准坐标与布局公式同源（`padBaseCenters`，203 行注释已自警"需同步"）。
- **组模式**（第 20 条，`padGroupSel`）：D-pad 十字、面键、双摇杆成组，点选后整组平移；**组移动不做单键吸附**（366 行注释："组相对位置不能被吸附改写"）。
- **配置卡**（623–682）：画在面板 `Alignment.Center`，键位行点按 `nextBit` 循环切 14 键、尺寸行 `nextSize` 循环切 4 档（40/44/58/76）；功能键（Exit/Edit）只出尺寸行（`FUNC_SLOTS`）；摇杆不进卡（`STICK_SLOTS` 只存偏移）。
- **存档**（`GamepadPadConfig`，SharedPreferences `apx_gamepad_pad`）：`bit.<slot>` / `size.<slot>` / `offx.<slot>` / `offy.<slot>` 四键前缀，槽位 16 个（A/B/X/Y/L1/R1/L2/R2/Sel/Start/DUp/DDown/DLeft/DRight/Exit/Edit）+ 摇杆 2 个；`padConfigVersion` bump 触发全部按钮重读。

## 二、问题清单（按优先级）

| # | 问题 | 证据位置 | 影响 |
|---|---|---|---|
| P1 | 改键只能 `nextBit` 循环：14 个键改到目标平均点 7 下，点过头要绕圈 | GamepadPadConfig.nextBit、Activity 652–656 | 用户点名要改的「改键方式」 |
| P2 | 无撤销、无恢复默认：拖动/缩放每帧直写存档，误拖误捏即永久生效 | Pad 手势 963/977、Stick 811 | 误操作不可回退 |
| P3 | 配置卡固定居中：可能盖住正在编辑的按钮，也不能拖走 | Activity 626 | 编辑遮挡 |
| P4 | 组模式与吸附互斥：整组平移不贴轴，对齐手感与单键不一致 | Activity 366 | 体验不统一 |
| P5 | `padConfigVersion` 全量重读：改一颗键全部按钮重组重读 16×4 键存档 | Activity 248、865 | 性能小瑕疵，不可感知，后置 |

**做对了的部分（不改）**：编辑态抑制 HID 输出（与 scrcpy-touchmap「编辑中禁触控注入」的硬要求一致）；拖心=移动、拖缘=缩放的双区手势（与 touchmap 同构）；多指逐指认领；功能键无键位时隐藏键位行（第 21 条）。

## 四、方案设计

### 本批（P0：改键方式 + 恢复默认）

**1. 键位选择网格（替换 nextBit 循环）**

- 交互：配置卡键位行改为可点开（文案「键位」+ 当前值），展开后为 14 键网格（每行 5 键，3 行；PS 布局符号与 `KEY_CHOICES` 一致）；当前键位用 `overlay_pad_ok` 描边高亮；点任一键即落盘并保持展开（方便连改多颗），点键位行或「完成」收起。
- 实现：配置卡 `Column` 内新增展开态 `var keyPickerOpen by remember(slot) { mutableStateOf(false) }`；网格用 `Row + chunked(5)`（不引第三方布局库）；每格为小圆钮，配色沿用 `overlay_pad_key_idle/stroke_*` token，禁 `Color(0x…)` 字面量；点击调 `GamepadPadConfig.set(cfgCtx, slot, newBit, curSize)` + `padConfigVersion++` + haptic。`nextBit` 保留（网格内不再使用，函数删除与否随实施时定，避免留死代码）。
- 点按热区：格子 44dp 起，满足"行高 44dp 起好点按"的既有口径。

**2. 尺寸档选择条（与键位网格同一交互语言）**

- 「尺寸」行点开横向四档（40/44/58/76）+ 当前档高亮；点选即落盘。`nextSize` 同上处理。
- 捏边无级缩放不变（实时值优先于配置档，见第 18 条）；档位条与无级值以最近档显示。

**3. 配置卡加「恢复默认」行**

- 交互：卡内第三行「恢复默认」（功能键也有此行）；点击清该槽位 `bit/size/offx/offy` 四键，`padConfigVersion++`，带一次 haptic；不弹确认（改动可再调回来，且编辑态本身不发光标）。
- 实现：`GamepadPadConfig` 新增 `reset(ctx, slot)`：对四个 KEY 前缀 `remove`；默认值回落 `SLOT_DEFAULTS` 与 offset (0,0)，读端逻辑不变。
- 存档兼容：不新增 key、不迁移，老配置直接兼容。

**4. 文案走 strings.xml**

- 新增文案：`键位`、`尺寸`、`恢复默认`、`完成`（现状硬编码中文的 `自定义：$slot` 顺手迁入，格式化参数用 `%1$s`）。遵循棘轮基线（当前 674），只增不减既有条目；`ui/` 内不出现实现词。

### 二期（P1：误操作兜底）

**5. 编辑会话快照 + 撤销**

- 进编辑态（✎）时对 `apx_gamepad_pad` 全量快照（16 槽 × 4 键）内存持有；编辑面板加「撤销」：退回进编辑态时的快照（等价 touchmap「丢弃改动=从盘重载」，但兜住整个会话而非单次拖动）；✓ 收工即提交、快照释放。
- Key Mapper 式多步 undo/redo 栈：放三期（收益 vs 复杂度，单步全量撤销已覆盖主要误操作场景）。

### 三期（P2：体验补齐）

**6. 配置卡跟手**：卡弹在目标按钮就近象限（按钮中心到面板四角距离取最近的角内缩 16dp 定位），仍画在面板内不换 Dialog（Service overlay 宿主 BadToken 规避不变）。

**7. 组吸附**：组模式下以**组包围盒**贴轴（轴命中判定用组内各槽位中心，吸附时整组平移同量、组内相对位置不变）——与 366 行"组相对位置不能被吸附改写"的注释意图一致，只是把单键轴换成组盒轴。

**8. 配置版本粒度**：`padConfigVersion` 改为按槽位 `Map<String, Int>` 或直接以 `padConfiguring`/受影响槽位 state 驱动重组，消除全量重读（P5，纯性能，无可感知收益，最后做）。

## 五、不做的事

- 不引第三方 UI/手势库；不改 HID 协议与报告格式（只动本端换算表）。
- 不做「按实体键绑定」（手机端无实体键可按，见第三节）。
- 不做撤销/重做进存档层（只做会话内存级）。

## 六、验收清单

- [ ] 改键：任意槽位点开网格，一点即中；当前键位高亮；连改多颗不收卡。
- [ ] 尺寸：档位条点选生效；捏边缩放与档位条互不冲突（实时值优先）。
- [ ] 恢复默认：单槽位四个维度（键位/尺寸/偏移 x/y）全部回落；功能键可恢复尺寸与位置。
- [ ] 撤销：进编辑→乱改→撤销，回到进编辑时布局；✓ 后撤销入口消失。
- [ ] 存档：老版本配置升上来直接可用；冷启动读档不回退。
- [ ] 文案：新增中文全在 strings.xml，棘轮基线更新；`scripts/check_*.py` 11 项全绿；`python3 scripts/finish_task.py --message …` 收尾。
